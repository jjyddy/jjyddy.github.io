ret2libc 学习

简介

通过栈溢出漏洞使程序跳转到libc 中的bin/sh 执行shell

函数是否有动态链接！！！

ldd ./vuln

not a dynamic executable
不能 ret2libc

使用libc

checksec ./vuln
决定怎么用libc

NX : enabled 栈不可执行

考虑用ret2libc

PIE : 程序地址随机化

NO

直接用

Yes

获取到程序基地址

Canary(栈保护)

No

溢出即可

Yes

需要绕过 (比较难)

前置(寻找plt与got地址)

使用libc 里的函数第一次会调用 plt 跳转到 got 表
此时 got 表中 没有该函数地址， 会加载函数进got表，第二次调用会直接使用该地址
因此在第二次进入时可以打印 got表中的值 (即函数真实地址)

code:

elf = ELF(‘./vuln’)
func_plt = elf.plt[‘func’]
func_got = elf.got[‘func’]

或在ida上查找 (不过python万岁)

步骤

  1. 泄露 libc 地址（leak）
  2. 计算 libc 基址
  3. 调用system(“/bin/sh”) 获取 shell

FirstPart

由于libc库中的函数偏移是一定的 (对于同一个libc来说)

我们使用write puts 都是使用的libc库中的函数
于是我们可以通过偏移来使用库中的函数

即 libc_base + offset = fun_addr

但是一般程序都有ASLR 即地址随机化

使得每次libc 的基地址都会变 ， 于是需要先找到libc 地址才能进行

但是libc中函数相对 libc 的偏移是一定的

即 write_addr - off = libc_addr (其中off 可以由当前libc给出，因此确定libc的版本很重要)

SecondPart

由上一段

write_addr - off = libc_addr

得到基址

ThirdPart

找到system 地址 ， bin/sh (相当于开一个终端)

第二次对栈的返回地址覆盖
system + 0xdeafbeef + bin/sh
相当于调用系统函数

回忆一下 32bit 函数调用
call func -> push ret_addr
push ebp
mov ebp esp
sub esp xxxx

即 执行 system(bin/sh)

此时 system也有一个返回地址
call 会自动压入ret,而我们执行ret没有，需要手动补上

现在找到使用的libc

libc = ELF(“libc version”) 一般题目会给
然后

system_off = libc.symbols[‘system’]
write_off = libc.symbols[‘write’]
binsh_off = next(libc.search(b”/bin/sh”))

其中 symbol 用来找 函数/变量名
libc.symbol[…]

search 用来找 内存数据(比如字符串)
libc.search(next(‘bin/sh’)) 值得注意的是可能有多个匹配 ， 需要 next 取第一个

x64 ret

64bit 与 32bit 区别在传参方式

32bit 使用 栈传递
64bit 优先使用 寄存器rdi，rsi，rdx，rcx，r8，r9(一共六个) ,后续参数使用栈传参

传参 用 pop rdi ; ret

shell 输入 ROPgadget –binary ./vuln | grep “pop rdi”

eg:

0x00000000004011e3 : pop rdi ; ret

注意：64bit有一个栈对齐的坑
